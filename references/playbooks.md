# 调用序列手册 · Playbooks

`→` 顺序调用 · `⇒` 判断性工作（由 Agent 完成）· `⚠` 失败分支

---

## P0 · 主流程：生成完整消费足迹报告

适用："看看我的麦当劳消费记录 / 做个消费画像 / 生成足迹分享卡"

```
1. now-time-info
      → 拿到当前时间基准（只调一次）

2. order-list
      → 拿近期订单列表
      ⚠ 返回 0 条 → 告知用户"近期无可读取订单"，终止，不生成空报告
      ⚠ 429      → 退避后重试一次；仍失败则告知稍后再试

3. 对列表中每一笔 query-order
      → 拿商品明细、点餐方式、金额
      ⚠ 控制节奏，避免触发每分钟 600 次限流
      ⚠ 部分失败 → 保留成功的订单，并明确说明覆盖面

4. ⇒ normalize_orders.py
      → 原始返回落盘为 raw/（或单个 raw.json），再 --input raw/ --output orders.json
      → 首次拿到新版本返回先 --dump-keys，把实际键名补进脚本顶部 ALIASES
      → 四条硬规则：金额单位按文件判定（订单接口是元）/ 点餐方式归一到五种 / 不填 city 与 district / 优惠与券照实填
      ⚠ 报「没有识别出订单对象」→ 看 --dump-keys 结果补别名，不要手工编 JSON 绕过去
      ⚠ 报「金额超 2000 元」→ 用 --amount-unit fen|yuan 显式指定后重跑

5. footprint_aggregate.py
      → footprint.json
      ⚠ 出现「小计对不上」告警 → 回到第 4 步修映射，不要绕过
      ⚠ 订单 < 15 单 → 照常生成，但回复用户时要提示样本偏小

6. render_report.py --card-output
      → report.html + card.html

7. present_files 交付
      → 回复给 3–5 条关键结论 + 数据边界说明
      → 不把订单明细原文贴进聊天
```

## P1 · 只回答"我常去哪家店"

**不要跑完整五维流程。** 用能回答问题的最小调用集：

```
1. order-list
2. ⇒ 按门店聚合，直接回答
```

理由：用户问的是一个点，不是一张报告。裁剪后更快，也省限流额度。

---

## P2 · 只回答"优惠到底省了多少"

> 原本这一条是「麦金卡值不值」。实测确认接口不返回持卡字段，这条路径**不再存在**，
> 替换成同样轻量、但数据真实可得的优惠核算。

```
1. order-list + query-order
      → 需要每一单的 totalAmount / realTotalAmount / totalDiscountAmount / couponList
      ⚠ 若 totalDiscountAmount 全为 0 或缺失 → 直接说明"当前返回里没有优惠数据"，不要估算

2. ⇒ normalize_orders.py（discount_fen 与 coupons 会一并规范化）

3. footprint_aggregate.py
      → 只看 discount_ledger 区块，回答三件事：
        原价 → 实付 → 省下，以及每张券各贡献多少
      → 自洽校验：原价 − 省下 必须等于实付
```

---

## P3 · 只看时间节律

```
1. order-list（时间字段通常列表页就有，可少调 query-order）
2. ⇒ 规范化（商品明细可留空数组）
3. footprint_aggregate.py → 读 time_heatmap 与 weekday_mix
```

注意：商品明细留空时，品类与单品维度为空，报告会自动跳过这两个区块。

## 失败分支总表

| 现象 | 处理 |
|---|---|
| 401 | Token 失效 → 提示去 open.mcd.cn 重新激活，**不重试** |
| 429 | 退避后重试一次；仍失败则告知稍后再试 |
| `order-list` 返回 0 条 | 如实告知，**不造报告** |
| `query-order` 部分失败 | 保留成功订单，明确说明覆盖范围 |
| 门店地址解析不出城市 | 该单进总额但不进城市维度；报告会告警 |
| 小计对不上 | 回规范化步骤修映射 |
| 接口不返回持卡字段 | 不做「麦金卡回本」结论，改答优惠账本并说明原因 |

---

## 裁剪原则

**用户问什么就答什么。** 一个具体问题用最小调用集解决，
不要为了"跑完整流程"而调动全部工具——那样既慢，又多烧限流额度。
